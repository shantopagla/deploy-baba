## W-CHL.1 Purpose

Add a "Challenges" feature to showcase portfolio projects and technical challenges. Each challenge represents a significant project or technical problem solved, with rich metadata including tech stack, category, job linkage, and detailed descriptions. **As of ADR-036, `content/challenges/*.md` is the source of truth** — SQLite's `challenges` table is a read-optimized cache refreshed from disk via `content_sha` freshness checks, and served as JSON via public API endpoints to the React SPA. Challenges are integrated into the RAG system as the 7th corpus for AI-powered Q&A about portfolio projects; RAG ingest refreshes the cache from `content/challenges/*.md` before chunking.

## W-CHL.2 Public API Surface

| Route | Method | Auth | Description |
|-------|--------|------|-------------|
| `/api/challenges` | GET | Public | List all challenges ordered by sort_order |
| `/api/challenges/{slug}` | GET | Public | Get single challenge by slug |
| `/api/jobs/{slug}/challenges` | GET | Public | Get challenges linked to a specific job |

There is no admin write API for challenges (`POST/PUT/DELETE /api/admin/challenges*` were
removed in ADR-036). Content changes go through `content/challenges/*.md` +
`just challenges-migration`.

## W-CHL.3 Implementation Notes

### Content Source (ADR-036, 2026-07-08)

`content/challenges/<slug>.md` is the source of truth. YAML frontmatter carries scalar/
list fields (`title`, `job_slug`, `short_description`, `tech_stack`, `category`, `url`,
`image_url`, `featured`, `sort_order`, `related_plan_module`, `related_adr`); the markdown
body carries `## Description` / `## Problem` / `## Constraints` / `## Decisions` /
`## Implementation` / `## Outcomes` / `## Metrics` sections for the long-text fields.

`xtask/src/challenges.rs` implements the sync tooling (`just challenges-sync`,
`just challenges-diff`, `just challenges-migration` — see ADR-036 for the full command
surface and why `gen-migration` is the only channel that reaches production).

### Schema

Single `challenges` table with optional job linkage and categorization:

```sql
CREATE TABLE IF NOT EXISTS challenges (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    slug              TEXT    NOT NULL UNIQUE,
    title             TEXT    NOT NULL,
    job_id            INTEGER REFERENCES jobs(id),
    description       TEXT    NOT NULL,
    short_description TEXT,
    tech_stack        TEXT,
    category          TEXT,
    url               TEXT,
    image_url         TEXT,
    featured          INTEGER NOT NULL DEFAULT 0,
    sort_order        INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_challenges_job_id ON challenges(job_id);
```

### Migrations

- `022_create_challenges.sql` — schema + index + 4 seeded challenges (deploy-baba portfolio, 27-step platform deployment, Scala multi-tenancy, RAG grounding system). Left untouched (migrations are immutable history) — still the bootstrap seed for a brand-new empty DB.
- `038_challenges_content_sha.sql` — adds nullable `content_sha` column, the freshness signal `xtask challenges` uses to detect repo-newer-than-DB.
- `NNN_challenges_content_<date>.sql` — generated by `just challenges-migration` whenever `content/challenges/*.md` changes; always layers on top of 022/030 and wins for any slug present in `content/challenges/`.

### Route Handler Pattern

Follows `routes/api/jobs.rs` pattern: `row_to_challenge()` helper converts SQLite rows to Challenge structs with comma-separated tech_stack parsing. Three handlers (`list_challenges`, `get_challenge`, `list_challenges_for_job`) return JSON consumed by React SPA.

### RAG Integration

Challenges are integrated as the 7th RAG corpus:
- `xtask/src/rag.rs::ingest()` calls `challenges::sync()` before `index_portfolio_data()` —
  the RAG-side freshness refresh required by ADR-036, so retrieval never serves stale
  challenge prose relative to `content/challenges/*.md`.
- `crates/rag-core/src/portfolio.rs`: `get_challenges_summary()` method for live-data retrieval (reads the SQLite cache, unaffected by ADR-036 — it stays fresh because `ingest()` synced first)
- `crates/rag-core/src/chunk/portfolio.rs`: `challenge_to_prose()` function converts challenge entities to prose chunks
- `crates/rag-core/src/hybrid.rs`: "challenge"/"challenges" keyword triggers for filtered retrieval
- Challenges linked to jobs enable cross-corpus queries (challenges → jobs → competencies)

### UX

- Admin dashboard: list view with featured badges, detail view with full metadata
- Category badges: fullstack, platform, ai (displayed in admin UI)
- Featured flag: highlights important challenges in list view
- Sort order: manual ordering for display priority

  create/edit/delete controls (`ChallengeDetail.test.tsx`, `Challenges.test.tsx`)
- Verify RAG retrieval includes challenges corpus for relevant queries
- Verify `just challenges-sync` is idempotent (`0 synced, N skipped, 0 pruned` on re-run)
  and prunes rows whose `.md` file was deleted
- Verify `just challenges-diff` exits non-zero on drift and 0 on a clean tree (CI gate)
- Verify `just challenges-migration` emits a valid ADR-010 migration file that applies
  cleanly on top of 022/030
